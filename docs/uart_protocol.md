# BuddyBot USB 시리얼 프로토콜 사양

## 개요

이 문서는 BuddyBot에서 라즈베리 파이 5(Brain)와 라즈베리 파이 피코(Spinal Cord) 간 텍스트 기반 USB 시리얼 통신 프로토콜을 지정합니다.

## 설계 근거

### 텍스트 기반 프로토콜이 필요한 이유

USB 시리얼 프로토콜은 바이너리 형식 대신 사람이 읽을 수 있는 텍스트 메시지를 사용합니다:

- **디버깅**: 시리얼 모니터를 사용하여 직접 읽고 이해 가능
- **개발 속도**: 초기 개발 중 커스텀 패킷 파서 불필요
- **신뢰성**: 안전-critical 시스템에서 소프트웨어 버그 감소
- **유연성**: 펌웨어 업데이트 없이 새 명령 추가 가능
- **안전**: 명확한 오류 감지 및 복구

### USB 시리얼이 프로세서 간 통신에 필요한 이유

- **결정론적**: 고정 타이밍, 네트워크 유발 지연 없음
- **격리됨**: WiFi/네트워크 문제의 영향을 받지 않음
- **저지연**: 실시간 제어를 위한 마이크로초 단위 통신
- **단순**: 안전-critical 경로에 최소 소프트웨어 복잡성
- **표준**: USB CDC 클래스 드라이버로 즉시 사용 가능

## 프로토콜 특성

- **텍스트 기반**: 사람이 읽을 수 있는 ASCII 명령
- **라인 기반**: 각 메시지가 개행(\n)으로 끝남
- **쉼표 구분**: 필드가 쉼표로 구분됨
- **키-값 쌍**: 선택적 파라미터가 key=value 형식 사용
- **대소문자 구분**: 모든 명령과 응답이 대문자
- **견고함**: 잘못된 패킷 무시, 승인 제공
- **비동기**: 필요 시 명령 전송, 사용 가능 시 응답 전송

## 메시지 형식

```
COMMAND[,param1[,param2[...]]]\n
RESPONSE[,param1=value1[,param2=value2[...]]]\n
```

## 명령 (Pi 5 → Pico)

### HB - 하트비트
- **목적**: 워치독 타이머 활성 유지, 시스템 응답성 확인
- **형식**: `HB`
- **예시**: `HB`
- **응답**: `ACK,HB`
- **주기**: 활성 작동 시 100-200ms마다

### CMD - 속도 명령
- **목적**: 정규화된 좌표로 로봇 속도 설정
- **형식**: `CMD,vx,vy,wz`
- **파라미터**:
  - `vx`: 전진 속도 (-1.0 ~ 1.0, 1.0 = 최대 전진)
  - `vy`: 측면 속도 (-1.0 ~ 1.0, 양수 = 왼쪽)
  - `wz`: 각속도 (-1.0 ~ 1.0, 양수 = 반시계 방향)
- **예시**: `CMD,0.5,0.0,0.2`
- **응답**: `ACK,CMD`
- **참고**: [-1,1] 범위를 벗어나면 클램핑됨. 영 값은 움직임 정지.

### BRAKE - 비상 브레이크
- **목적**: 안전을 위한 즉각 모터 정지
- **형식**: `BRAKE`
- **예시**: `BRAKE`
- **응답**: `ACK,BRAKE`
- **효과**: 모든 모터 즉시 정지, E-stop 래치

### CLEAR - 비상 정지 해제
- **목적**: 안전 조건이 해결된 후 비상 정지 래치 재설정
- **형식**: `CLEAR`
- **예시**: `CLEAR`
- **응답**: `ACK,CLEAR`
- **요구사항**: 안전 조건이 실제로 해결된 경우에만 작동

### MODE - 모드 업데이트 (선택)
- **목적**: 고수준 시스템 모드 변경에 대한 Pico 정보 제공
- **형식**: `MODE,name`
- **파라미터**:
  - `name`: 모드 이름 (IDLE, MANUAL, FOLLOW, NAV)
- **예시**: `MODE,NAV`
- **응답**: `ACK,MODE`
- **참고**: 로깅/디버깅용으로 주로 사용, Pico 동작 변경 안 함

## 응답 (Pico → Pi 5)

### ACK - 승인
- **목적**: 명령 수령 및 실행 확인
- **형식**: `ACK,type`
- **파라미터**:
  - `type`: 승인되는 명령 유형
- **예시**: `ACK,CMD`
- **타이밍**: 명령 처리 즉시 전송

### STAT - 상태 보고
- **목적**: 건강 및 상태에 대한 주기적 업데이트
- **형식**: `STAT,estop=value,timeout=value,mode=value,vbat=value`
- **파라미터**:
  - `estop`: 비상 정지 활성 (0=정상, 1=정지)
  - `timeout`: 워치독 타임아웃 발생 (0=정상, 1=타임아웃)
  - `mode`: 현재 작동 모드
  - `vbat`: 배터리 전압 (볼트)
- **예시**: `STAT,estop=0,timeout=0,mode=IDLE,vbat=12.3`
- **주기**: 작동 시 100ms마다

### RPM - 모터 RPM 요약
- **목적**: 폐루프 검증을 위한 실제 모터 속도 보고
- **형식**: `RPM,m1=value,m2=value,m3=value`
- **파라미터**:
  - `m1`: 모터 1 RPM (양수 = 전진)
  - `m2`: 모터 2 RPM
  - `m3`: 모터 3 RPM
- **예시**: `RPM,m1=150,m2=-120,m3=80`
- **주기**: 움직임 시 50ms마다

### SAFE - 안전 이벤트
- **목적**: 안전-critical 이벤트의 즉각 알림
- **형식**: `SAFE,reason`
- **파라미터**:
  - `reason`: 이벤트 설명 (WATCHDOG_TIMEOUT, ESTOP_BUTTON 등)
- **예시**: `SAFE,WATCHDOG_TIMEOUT`
- **타이밍**: 안전 이벤트 발생 즉시 전송

## 통신 흐름

### 정상 작동
1. Pi 5가 필요 시 `HB` 명령 전송하여 워치독 활성 유지
2. Pi 5가 움직임을 위해 `CMD` 명령 전송
3. Pico가 각 명령에 `ACK`로 응답
4. Pico가 주기적 `STAT` 및 `RPM` 업데이트 전송
5. 안전 이벤트가 트리거되면 즉시 `SAFE` 메시지 전송

### 비상 시퀀스
1. 안전 이벤트 발생 (버튼 누름, 워치독 타임아웃 등)
2. Pico가 `SAFE` 메시지 전송 및 모터 정지
3. Pi 5가 안전 상태 감지 및 적절 응답
4. 안전 조건 해결될 때까지 시스템 안전 상태 유지
5. 안전 해제 후 정상 작동 재개

## 오류 처리

### 잘못된 메시지
- 잘못된 명령 무시
- 잘못된 명령에 승인 전송 안 함
- 시스템 정상 작동 계속

### 통신 손실
- Pico 워치독이 500ms 후 트리거
- 모터 자동 정지
- `SAFE,WATCHDOG_TIMEOUT` 메시지 전송

### 버퍼 오버플로
- 고정 크기 버퍼가 오버플로 방지
- 버퍼 가득 차면 오래된 메시지 폐기
- critical 안전 메시지에 데이터 손실 없음

## 구현 참고사항

### Pi 5 (ROS 2) 구현
- 115200 baud로 시리얼 라이브러리 사용
- 라인 분할로 수신 파싱
- 타임아웃 및 재연결 처리
- ROS 토픽 및 서비스와 통합

### Pico (MicroPython) 구현
- UART 인터럽트 구동 수신
- 명령 파싱용 상태 머신
- 하드웨어 타이머로 워치독 타이머
- 다른 모든 명령 재정의 비상 정지

## 테스트 및 검증

### 프로토콜 테스트
- 수동 명령 테스트를 위한 시리얼 터미널
- 프로토콜 검증을 위한 자동화된 테스트 스크립트
- 고 명령률로 스트레스 테스트
- 견고성을 위한 오류 주입

### 통합 테스트
- 실제 하드웨어로 전체 시스템 테스트
- 안전 시스템 검증
- 부하 하 성능 테스트
- 장기 신뢰성 테스트

## 미래 확장

### 추가 명령
- `CAL`: 모터 교정 시퀀스
- `DIAG`: 진단 정보 요청
- `RESET`: 소프트웨어 리셋 명령

### 향상된 상태
- 개별 모터 온도
- 엔코더 위치 카운터
- 전력 소비 메트릭
- 진단 결함 코드
