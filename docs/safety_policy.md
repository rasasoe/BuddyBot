# BuddyBot 안전 정책

## 안전 철학

BuddyBot은 "안전 우선" 철학으로 설계되었으며, 모든 시스템 기능보다 인간 안전을 우선시합니다. 로봇은 기능성이나 성능을 희생하더라도 인간이나 재산에 해를 끼쳐서는 안 됩니다.

## 안전 원칙

### 방어적 깊이
안전은 독립적인 다중 계층으로 구현되어 하나의 계층이 실패하더라도 다른 계층이 보호를 제공합니다.

### Fail-Safe 기본값
모든 안전 메커니즘이 시스템 실패 시 가장 안전한 가능한 상태로 기본 설정됩니다. 모터 정지, 시스템 정지, 인간 개입이 필요합니다.

### 투명한 작동
안전 시스템 상태가 항상 표시되고 기록됩니다. 운영자가 안전 시스템이 활성화되는 이유를 이해할 수 있어야 합니다.

### 보수적 설계
안전 마진이 요구사항을 초과합니다.

## 안전 아키텍처 계층

### 계층 1: 하드웨어 안전
소프트웨어와 독립적으로 작동하는 물리적 보호 메커니즘.

#### 비상 정지 버튼
- **위치**: 로봇 섀시에서 접근 가능한 곳
- **기능**: 하드웨어 신호를 통한 즉각 모터 정지
- **리셋**: 수동 버튼 누름 필요
- **이유**: 인간 운영자에게 직접적이고 즉각적인 제어 제공

#### 모터 드라이버 안전장치
- **과전류 보호**: 과도한 전류로 인한 모터 손상 방지
- **열 정지**: 드라이버 과열 시 모터 정지
- **저전압 잠금**: 낮은 배터리에서 작동 방지

#### 전력 분배
- **격리된 전력 레일**: 안전 시스템용 별도 전력
- **퓨즈 보호**: 전기 화재 방지
- **배터리 모니터링**: 저전압 경고 및 정지

### 계층 2: 펌웨어 안전 (Pico)
마이크로컨트롤러 수준의 실시간 안전 강제.

#### 워치독 타이머
- **목적**: 시스템 무응답 감지
- **메커니즘**: Pi 5로부터 UART 통신 모니터링
- **타임아웃**: 유효 명령 없음 500ms
- **작동**: 자동 모터 정지
- **이유**: 소프트웨어 충돌로부터 "폭주 로봇" 시나리오 방지

#### 명령 검증
- **체크섬 검증**: 명령 무결성 보장
- **범위 확인**: 안전 제한 내 속도 명령 검증
- **타임아웃 모니터링**: 명령 중단 시 모터 정지

#### 엔코더 피드백 안전
- **스톨 감지**: 전력 하에 엔코더가 움직임을 표시하지 않으면 모터 정지
- **과속 보호**: 최대 휠 속도 제한
- **위치 제한**: 과도한 관절 이동 방지

### 계층 3: 소프트웨어 안전 (ROS 2)
고수준 안전 모니터링 및 조율.

#### 안전 감독자 노드
- **모니터링**: 모든 안전 소스 (E-stop, TTC, 명령 타임아웃)
- **작동**: 시스템 안전 상태 발행
- **통합**: 모드 변경 명령 및 네비게이션 취소

#### 충돌 감지
- **시간-충돌 (TTC)**: 즉각 위험 감지를 위한 비전 기반
- **LiDAR 장애물 감지**: 장거리 장애물 회피
- **복구 동작**: 안전 정지 및 경로 재계획

#### 명령 중재
- **우선순위 시스템**: E-STOP > Manual > Safety > Navigation > Follow > Idle
- **단일 소스**: 한 번에 하나의 명령 소스만 활성
- **타임아웃 보호**: 명령이 새로 고쳐지지 않으면 만료

### 계층 4: 시스템 안전
운영 절차 및 인간 요인.

#### 작동 모드
- **IDLE**: 안전 정지 상태
- **MANUAL**: 직접 인간 제어, 안전 모니터링 포함
- **AUTONOMOUS**: 완전 자율, 포괄적 안전 포함

#### 운영자 교육
- **안전 브리핑**: 작동 전 필수
- **비상 절차**: 명확한 정지 지침
- **유지보수 프로토콜**: 안전한 서비스 절차

## 안전 트리거 및 응답

### 비상 정지 트리거
1. **물리적 E-Stop 버튼**: 즉각 하드웨어 정지
2. **소프트웨어 E-Stop**: 프로그래매틱 비상 정지
3. **워치독 타임아웃**: Pi 5 통신 손실
4. **중요 센서 실패**: 안전-critical 센서 손실
5. **운영자 명령**: 수동 비상 정지

### 안전 응답 계층
```
CRITICAL 안전 (즉각 작동 필요)
├── 모터 정지
├── 시스템 정지
└── 인간 개입 필요

WARNING 안전 (성능 저하 작동)
├── 속도 감소
├── 기능 제한
└── 운영자 알림

NORMAL 안전 (표준 작동)
├── 지속 모니터링
├── 자동 복구
└── 성능 최적화
```

## 안전 검증 및 테스트

### 안전 시스템 테스트
- **단위 테스트**: 개별 안전 컴포넌트
- **통합 테스트**: 안전 시스템 상호작용
- **시스템 테스트**: 엔드투엔드 안전 시나리오
- **필드 테스트**: 실제 환경 안전 검증

### 안전 메트릭
- **거짓 양성률**: 불필요한 안전 활성화
- **응답 시간**: 트리거에서 안전 상태까지 시간
- **복구 시간**: 정상 작동 재개까지 시간
- **신뢰성**: 안전 실패 간 평균 시간

### 안전 문서화
- **위험 분석**: 잠재적 위험 식별
- **위험 평가**: 위험 수준 평가
- **완화 전략**: 안전 제어 구현
- **테스트 기록**: 안전 메커니즘 검증

## 운영 안전 절차

### 사전 작동 점검
1. **물리적 검사**: 모든 안전 하드웨어 확인
2. **소프트웨어 검증**: 안전 시스템 작동 확인
3. **배터리 점검**: 안전 작동을 위한 충분한 전력 확인
4. **영역 정리**: 작동 영역이 안전한지 확인

### 작동 중
1. **지속 모니터링**: 로봇 동작과 안전 표시기 관찰
2. **비상 준비**: E-stop 위치 파악 및 정지 절차 숙지
3. **통신**: 로봇 상태에 대한 인식 유지
4. **개입**: 필요한 경우 개입 준비

### 작동 후
1. **시스템 정지**: 적절한 전원 차단 절차
2. **데이터 검토**: 안전 이벤트에 대한 로그 확인
3. **유지보수**: 안전 시스템 문제 해결
4. **문서화**: 사고나 이상 기록

## 안전 준수

### 표준 정렬
- **ISO 13482**: 개인용 로봇 안전 요구사항
- **IEC 60204-1**: 기계 안전 - 전기 장비
- **ANSI/RIA R15.06**: 산업 로봇 안전 요구사항

### 인증 목표
- **CE 마킹**: 유럽 안전 준수
- **UL 인증**: 미국 안전 표준
- **산업 모범 사례**: 로봇 안전 가이드라인
