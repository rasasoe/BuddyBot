# BuddyBot 시스템 아키텍처

## 시스템 개요

BuddyBot은 라즈베리 파이 5 + 라즈베리 파이 피코 기반 자율 주행 홈 어시스턴트 로봇으로, 인간-로봇 상호작용을 위한 Brain vs Spinal Cord 아키텍처를 구현합니다. 이 시스템은 고수준 인지 기능을 저수준 안전-critical 모터 제어로부터 분리합니다.

## 설계 근거

### Brain vs Spinal Cord 아키텍처가 필요한 이유

Brain vs Spinal Cord 아키텍처는 안전성을 극대화하면서 시스템 유연성을 유지하기 위해 선택되었습니다:

- **안전 격리**: 모터 제어는 메인 컴퓨터(Pi 5)의 소프트웨어 실패로부터 영향을 받지 않는 별도의 마이크로컨트롤러(Pico)에서 실행됩니다
- **Fail-Safe 작동**: "뇌"(Pi 5)가 실패하더라도 "척수"(Pico)가 자동으로 모든 모터를 정지시킵니다
- **실시간 성능**: 저수준 제어 루프가 OS 오버헤드 없이 고주파수로 실행됩니다
- **모듈식 개발**: 비전, 네비게이션, 음성 처리를 독립적으로 개발할 수 있습니다

### 하드웨어 컴포넌트 역할

#### 라즈베리 파이 5 (뇌)
- **역할**: 고수준 인지, 계획, 조율
- **책임**:
  - ROS 2 미들웨어 및 노드 조율
  - 컴퓨터 비전 처리 (사람 감지, 추적)
  - 네비게이션 계획 및 웨이포인트 관리
  - 음성 인터페이스 및 자연어 처리
  - 시스템 모니터링 및 진단
- **Pi 5 선택 이유**: AI 워크로드에 충분한 컴퓨팅 파워를 제공하면서 적절한 전력 소비 유지

#### 라즈베리 파이 피코 (척수)
- **역할**: 실시간 모터 제어 및 안전 강제
- **책임**:
  - 옴니휠 모터용 PID 모터 제어
  - 엔코더 피드백 처리
  - 워치독 타이머 모니터링
  - 비상 정지 처리
  - Pi 5와 UART 통신
- **Pico 선택 이유**: 결정론적 실시간 성능, 저전력, 독립 작동

#### LiDAR 센서
- **역할**: 글로벌 네비게이션 및 매핑
- **책임**:
  - SLAM (동시적 위치추정 및 지도작성)
  - 장거리 장애물 감지
  - 자율 네비게이션용 경로 계획
- **LiDAR 선택 이유**: 조명 조건에 관계없이 신뢰할 수 있는 거리 측정 제공

#### 카메라 시스템
- **역할**: 로컬 안전 및 사람 상호작용
- **책임**:
  - 사람 감지 및 추적
  - 시간-충돌 추정
  - 제스처 인식
  - 추적용 비주얼 서보잉
- **카메라 선택 이유**: 자연스러운 인간-로봇 상호작용과 근거리 안전 모니터링 가능

## 소프트웨어 아키텍처

### ROS 2 패키지 구조

```
buddybot_base/      # Pi 5 ↔ Pico 통신 브리지
buddybot_vision/    # 컴퓨터 비전 파이프라인
buddybot_nav/       # 네비게이션 및 매핑
buddybot_system/    # 명령 중재 및 안전
buddybot_voice/     # 음성 인터페이스 (계획)
buddybot_bringup/   # 시스템 런치 구성
```

### 명령 멀티플렉싱 시스템

#### 명령 Mux가 필요한 이유

여러 서브시스템이 동시에 움직임 명령을 생성할 수 있습니다:
- 네비게이션 시스템이 웨이포인트로 이동하려 함
- 비전 시스템이 사람을 따라가려 함
- 수동 제어가 조이스틱/키보드로 입력됨
- 안전 시스템이 비상 정지를 원함

**멀티플렉싱 없음**: 명령이 충돌하여 위험한 동작 유발
**멀티플렉싱 있음**: 우선순위 기반 중재로 단일 진실 공급원

#### 명령 우선순위 계층

```
E-STOP (최고 우선순위)
├── 물리적 비상 정지 버튼
└── 소프트웨어 안전 트리거

MANUAL
└── 직접 사용자 제어

SAFETY
└── 충돌 회피

NAVIGATION
└── 자율 웨이포인트 추적

FOLLOW
└── 사람 추적

IDLE (최저 우선순위)
└── 모든 움직임 정지
```

### 안전 아키텍처

#### 워치독과 E-Stop 래치가 필요한 이유

**워치독 타이머**: 시스템 응답성 보장
- Pico가 Pi 5로부터 USB 시리얼 통신 모니터링
- 유효 명령이 없으면 타임아웃 후 모터 정지
- 소프트웨어 충돌로 인한 "폭주 로봇" 시나리오 방지

**E-Stop 래치**: 안전한 비상 정지 동작 제공
- 비상 정지가 명시적으로 해제될 때까지 활성 상태 유지
- 위험한 재시작을 방지하기 위해 운영자 의식적 행동 요구
- 일시적 결함으로 인한 우발적 재시작 방지

#### 안전 계층

1. **하드웨어 계층**: 물리적 E-stop 버튼, 모터 드라이버 안전장치
2. **펌웨어 계층**: Pico 워치독, 과전류 보호
3. **소프트웨어 계층**: ROS 안전 감독자, 충돌 감지
4. **시스템 계층**: 명령 중재, 모드 관리

## 통신 아키텍처

### USB 시리얼 프로토콜 설계

#### 텍스트 기반 프로토콜이 필요한 이유

USB 시리얼 프로토콜은 바이너리 형식 대신 사람이 읽을 수 있는 텍스트 메시지를 사용합니다:

- **디버깅**: 시리얼 모니터를 사용하여 직접 읽고 이해 가능
- **개발 속도**: 초기 개발 중 커스텀 패킷 파서 불필요
- **신뢰성**: 안전-critical 시스템에서 소프트웨어 버그 감소
- **유연성**: 펌웨어 업데이트 없이 새 명령 추가 가능
- **안전**: 명확한 오류 감지 및 복구

#### 메시지 형식

```
Pi 5 → Pico: CMD,vx,vy,wz
Pico → Pi 5: STAT,estop=0,timeout=0,mode=NORMAL
```

### ROS 2 통합

#### 토픽 기반 통신

```
/buddybot/cmd_vel          # 최종 중재된 속도 명령
/system/safety_active      # 시스템 전반 안전 상태
/nav/current_waypoint      # 네비게이션 상태
/vision/person_detected    # 비전 시스템 출력
```

#### 서비스 기반 제어

```
/system/mode_request       # 시스템 작동 모드 변경
/nav/waypoint_request      # 의미적 위치로 네비게이션
/safety/emergency_stop     # 비상 정지 트리거
```

## 시스템 모드

### 작동 모드 설계

모드는 상황 인식 동작 전환을 제공합니다:

- **IDLE**: 시스템 정지, 최소 처리
- **MANUAL**: 직접 사용자 제어, 안전 모니터링 포함
- **FOLLOW**: 비전 기반 사람 추적
- **NAVIGATION**: 자율 웨이포인트 네비게이션

### 모드 전환 로직

```
모든 모드 ──E-STOP──→ IDLE (래치)
IDLE ──수동 입력──→ MANUAL
MANUAL ──"Follow"──→ FOLLOW
FOLLOW ──"Navigate"──→ NAVIGATION
NAVIGATION ──"Stop"──→ IDLE
```

## 개발 고려사항

### 모듈식 이점

- **독립 테스트**: 각 서브시스템을 격리하여 테스트 가능
- **병렬 개발**: 팀원이 다른 패키지에서 작업 가능
- **기술 교체**: 비전 알고리즘이 네비게이션에 영향을 미치지 않고 업그레이드 가능
- **안전 검증**: 기능 개발과 독립적으로 안전 시스템 유지

### 성능 요구사항

- **실시간 제약**: 모터 제어 100Hz, 비전 30Hz
- **전력 관리**: 배터리 수명과 컴퓨팅 파워 균형
- **열 관리**: 지속 작동 시 과열 방지
- **네트워크 신뢰성**: WiFi 중단에도 강력한 작동

## 미래 확장성

아키텍처는 미래 향상을 지원합니다:

- **다중 로봇 조율**: 스웜 통신 추가
- **고급 AI**: 대형 언어 모델 통합
- **센서 융합**: IMU, GPS, 추가 카메라 추가
- **클라우드 통합**: 원격 모니터링 및 제어
- **학습**: 자율 기술 습득
